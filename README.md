## 写作原则

1. 先解释读者会遇到的现象，再解释它背后的机制，最后说明工程上怎样处理。
2. 区分模型、产品、运行框架和外部工具的责任；不把某一家的实现当成所有系统的通则。
3. 贯穿使用“查天气”和“修改文件”两个例子。新增概念要能接回这两条主线。
4. 对重要事实给出可核对的来源；示意数字和伪代码明确标为示意。
5. 按章节扩写，完成一章就检查与前后章节的衔接、术语和重复内容。
